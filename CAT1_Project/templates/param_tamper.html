🔀 Parameter Tampering

Modify a hidden price field before form submission to buy a ₹1,29,999 iPhone for ₹1 — then see how server-side validation stops it.

What is it?

Parameter Tampering exploits the fact that web forms pass data (prices, IDs, discounts) to the server via hidden fields or URL params. Attackers intercept and modify these values before submission.

Real-world impact

E-commerce sites have lost millions to price tampering — attackers buy items at manipulated prices. OWASP A04: Insecure Design. Fix: Never trust client-supplied prices — always validate server-side.

⚠️ Vulnerable Mode: The price is in a hidden form field. Edit it in DevTools (or use the tamper buttons below) before clicking Buy!
✅ Secure Mode: The server ignores the client price entirely. It fetches the real price from the DB — tampering is detected and blocked.

💻 Code Diff — What Changes

❌ Vulnerable — Trusts Client
# ⚠️ Reads price from the FORM # (client can change this!) paid_price = request.form.get( 'price', type=float # ← from client ) db.execute("INSERT INTO orders VALUES (?, ?)", (product_name, paid_price))
☠️ Client sends price=1 → order recorded at ₹1. The server never checks the real price.
✅ Secure — Server Validates
# ✅ Ignores client price ENTIRELY # Fetches real price from DB product_id = request.form.get('product_id') row = db.execute( "SELECT price FROM products WHERE id=?", (product_id,) ) server_price = row['price'] # ← from DB db.execute("INSERT INTO orders VALUES (?, ?)", (product_name, server_price))
✅ Client price is completely ignored. The authoritative DB price is always used.
