💉 SQL Injection Attack

Inject malicious SQL into a login form to bypass authentication — then see how parameterized queries stop it cold.

What is it?

SQL Injection occurs when user-supplied input is embedded directly into a SQL query string. An attacker can alter query logic to bypass authentication, dump tables, or delete data.

Real-world impact

Heartland Payment Systems (2008) — 134M card records stolen via SQLi. Ranked #1 in OWASP Top 10 for years. Fix: Always use parameterized queries.

💻 Code Diff — What Changes

❌ Vulnerable Code
# ⚠️ DANGEROUS — string concatenation username = request.form['username'] password = request.form['password'] query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'" result = db.execute(query)
☠️ Input like admin' -- becomes part of the query logic — bypasses the password check entirely.
Secure Code
# SAFE — parameterized query username = request.form['username'] password = request.form['password'] query = "SELECT * FROM users WHERE username=? AND password=?" result = db.execute(query, (username, password))
The DB treats user input as a value, never as SQL code. Any injection attempt is neutralized.
