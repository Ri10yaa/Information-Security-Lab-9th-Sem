⚡ Cross-Site Scripting (XSS)

Inject JavaScript into a comment board that runs in every visitor's browser — then see how HTML escaping makes it completely harmless.

What is it?

XSS occurs when user-supplied data is rendered as HTML/JS without sanitisation. The injected script runs in the victim's browser with the same privileges as the site — able to steal cookies, redirect, or deface the page.

Real-world impact

Samy Worm (MySpace, 2005) — 1 million profiles infected in 20 hours via XSS. British Airways (2018) — card data of 380K customers stolen via injected script. Fix: Always escape HTML output.

⚠️ Vulnerable Mode: Comments are rendered as raw HTML. Any injected <script> tag will execute!
✅ Secure Mode: Input is HTML-escaped before rendering. Tags like <script> appear as plain text.

Vulnerable — Raw innerHTML
# Python — stores raw content content = request.form['content'] db.execute("INSERT INTO comments VALUES (?, ?)", (author, content)) // JavaScript — renders as HTML div.innerHTML = comment.content // <script> tags EXECUTE here
innerHTML parses HTML — any script in the comment runs immediately.
✅ Secure — HTML Escaping
# Python — escape before storing import html content = html.escape(request.form['content']) db.execute("INSERT INTO comments VALUES (?, ?)", (author, content)) // JavaScript — safe rendering div.textContent = comment.content // ✅ <script> shown as text, not run
✅ html.escape() converts < → &lt; — tags are displayed, never executed.
